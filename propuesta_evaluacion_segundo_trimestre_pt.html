¿Qué se busca construir?

Un prototipo que observe el tráfico dirigido al Contramuseo, extraiga características medibles y utilice un modelo de aprendizaje automático para distinguir comportamiento normal de actividad compatible con un ataque DDoS. En el segundo trimestre se busca llegar hasta la detección y alerta; en el tercero se integrarán la mitigación, el dashboard y el despliegue en Raspberry Pi.

Función del Contramuseo: será el servicio web que se protege y el entorno donde se genera tráfico de prueba. El objetivo principal del PT sigue siendo la detección DDoS con IA, no construir un CMS completo.

Entregables evaluables del segundo trimestre

Entregable Qué debe demostrar Evidencia sugerida Valor
1. Infraestructura funcional Nginx, Flask y SQLite levantan con Docker Compose; el Contramuseo y la API responden. Repositorio, diagrama, docker compose up, rutas de prueba y logs. 15 %
2. Datos y características Existe un protocolo reproducible para generar tráfico normal/anómalo y convertirlo en variables numéricas. Scripts, muestra del dataset, diccionario de variables y separación entrenamiento/prueba. 20 %
3. Modelo y evaluación El modelo se compara con una regla base y se evalúa con datos no usados durante el entrenamiento. Notebook o script, matriz de confusión, precisión, recall, F1 y análisis de falsos positivos. 30 %
4. Monitor con alertas El sistema procesa tráfico nuevo y genera una alerta durante una prueba local controlada. Demostración, salida de consola y registro de tiempo de detección. 20 %
5. Documentación y explicación El alumno explica el flujo completo y documenta arquitectura, decisiones, pruebas, resultados y limitaciones. Documento LaTeX actualizado, capturas, bitácora y exposición. 15 %
Total Propuesta de ponderación ajustable por el asesor. 100 %

Resultado esperado al terminar el segundo trimestre

  • El proyecto se levanta de forma reproducible con Docker Compose.
  • Nginx sirve el Contramuseo, envía la API a Flask y produce logs utilizables.
  • Existe un conjunto de datos de laboratorio con tráfico normal y anómalo.
  • El extractor genera las mismas variables para entrenamiento e inferencia.
  • El modelo tiene métricas sobre datos de prueba separados.
  • Una prueba controlada provoca una alerta visible y auditable.
  • El documento de PT incluye arquitectura, metodología y resultados preliminares.
  • No se bloquean IP automáticamente todavía; primero se validan falsos positivos.
